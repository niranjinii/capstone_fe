# Privacy-Preserving Cancer Risk Prediction via Functional Encryption

A 3-party system for encrypted genomic inference using Function-Hiding Inner Product Encryption (FHIPE / FeDDH). A doctor can query a cloud server with an encrypted patient genome and receive a cancer risk score — without the cloud ever seeing the patient data or the model weights.

## Architecture

```
Hospital (Trusted KGC)         Clinic (Doctor)            Cloud (Untrusted)
─────────────────────         ──────────────────         ──────────────────
• Holds master key             • Holds patient data       • Holds nothing secret
• Holds ML model weights       • Encrypts via delegated   • Evaluates encrypted
• Issues functional keys         encryption key (ek)        dot product
• Runs on port 5001            • Runs as a script         • Runs on port 5002
```

## Quick Start

```bash
# Prerequisites: Linux/WSL with Python 3.10+
source .capstone/bin/activate

# Terminal 1: Start the Hospital (KGC)
python hospital.py --model 0    # 0 = ACC, change index for other cancers

# Terminal 2: Start the Cloud
python cloud.py

# Terminal 3: Run the Clinic query
python clinic.py
```

## Key Technical Details

- **Encryption scheme:** FeDDH (Function-Hiding Inner Product Encryption) via PyMIFE
- **Backend:** `mclbn256` (C++ BN256 pairing library) — ~500x faster than `py_ecc`
- **Key generation:** Custom Gaussian elimination (`fast_feddh_generate`) — reduced setup from 7min to 20s
- **Delegated encryption:** Clinic encrypts in O(n²) exponentiations instead of O(n³)
- **Quantisation:** Constant-shift approach preserves negative Lasso coefficients while avoiding PyMIFE's zero-weight bug
- **Serialization:** Custom JSON serializer for mclbn256 group elements (G1, G2, GT)
